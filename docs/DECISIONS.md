# Решения по дизайну и архитектуре

Формат: дата · сессия · вопрос → решение · почему.

## 2026-10-14 · сессия 00 (предварительные правки без Godot)

Сделано на машине без Godot, **не запускалось**. Сессия 01 начинается с проверки этих правок.

- **Фокус в HUD (прыжок открывал окна)** → всем `Control` внутри HUD, кроме полей ввода, ставится `FOCUS_NONE` через `SceneTree.node_added`. · Окна (таланты, книга, персонаж, лавка, настройки) создаются при первом открытии, поэтому одно место надёжнее, чем помнить про `focus_mode` в каждом файле. Заодно Tab больше не уходит в навигацию фокуса.
- **Длительность передышки** → настройка партии `Net.settings["break"]`, 30/60/90 сек., по умолчанию 60. Выбирается на экране героя рядом с длительностью и направлениями. · Пользователь попросил минуту. Выбор хоста дёшев и позволяет ускорить игру опытной группе.
- **Версия игры** → `application/config/version` в `project.godot` — единственный источник; между релизами с суффиксом `-dev`. Сравнение — точное совпадение строк. · Простое правило без семантического версионирования: играть вместе можно только на одной сборке.
- **Отказ по версии** → хост шлёт клиенту `_version_mismatch`, а отключает через 1 с, чтобы сообщение успело дойти. RPC назван так, чтобы по алфавиту стоять последним в `network.gd`: если номера RPC зависят от порядка имён, старые клиенты (v0.4) всё равно дойдут до `_register_player` и будут отклонены, а не вызовут чужой метод.
- **Ледяная стена уязвимее** → прочность 420 → 340 (−20%), а не повышенный урон мобов по стенам. · Одно число проще балансировать, и талант «Крепкий лёд» (+30% за ранг) сохраняет вес. Стадии повреждения (≤50%, ≤25%) сервер рассылает надёжным событием `ev_wall_damage` только при смене стадии: лёд тускнеет, осколки откалываются, звук треска.
- **Мобы бегают туда-обратно** — найдены три причины, исправлены все:
  1. `_lane_dist` искал полосу только около `m.wp`, а во время погони `wp` не обновляется. Моб, гнавшийся за героем вдоль дороги, считался «далеко от полосы» и бросал погоню, стоя на дороге. → Поиск ближайшего отрезка по всей полосе (8 точек — дёшево, считается 2–3 раза в секунду).
  2. Бросив погоню, моб шёл к старой точке маршрута позади себя. → `_drop_chase()` ставит ближайшую точку впереди.
  3. Погоня бросалась, если герой дальше 32 м, а маг бьёт с 34–36 м: урон → погоня → сброс через полсекунды → снова урон. → Цель бросается дальше 40 м (`CHASE_DROP_RANGE`). Поводок от полосы (32 м) прежний.

  Плюс гистерезис: бросив погоню по поводку, моб 2,5 с не берёт новую цель и не реагирует на урон (`REAGGRO_DELAY`). Уже атакующий моб не перестаёт бить, пока цель не уйдёт на 0,3 м (ближний бой) или 1,5 м (дальний бой) дальше дальности атаки — дальнобойные не «пилят» на краю. Если цель погибла, моб сразу ищет следующую, без задержки.
