# Сессия 08 — сборка в .exe и перенос мобов на C++

Перед началом прочитай `CLAUDE.md`, `README.md`, `docs/ROADMAP.md` и `docs/DECISIONS.md`. Лучше делать после сессий 02–03, когда ИИ мобов устоялся: иначе C++ придётся переписывать.

Цель:
1. Друзья получают обычную игру — `HeroSiege.exe` в архиве, без Godot внутри и `.bat`.
2. Самое горячее место, серверная симуляция мобов, работает на C++ и держит заметно больше мобов.

---

## 1. Сборка в .exe

- Шаблоны экспорта Godot 4.7.2 возьми **только с официального сайта** godotengine.org или с GitHub godotengine. Поставь их по стандартному пути.
- Создай `export_presets.cfg`, пресет Windows Desktop:
  - PCK встроен в exe;
  - иконка игры: сделай из имеющихся ассетов, `.ico`;
  - версия и название в свойствах файла;
  - выход в `export/` (папка в `.gitignore`).
- **Режим для старых видеокарт.** Сейчас его даёт «Играть (если не запускается).bat» с `--rendering-driver opengl3`. В exe сделай так же удобно:
  - либо второй ярлык или `.cmd` рядом с exe;
  - либо автоматический откат на OpenGL, если Vulkan не стартовал, — проверь, умеет ли это сам Godot 4.7;
  - плюс пункт в настройках игры «Режим совместимости (после перезапуска)».
- Скрипт `tools/release.ps1`: экспорт → архив `HeroSiege-vX.Y.zip` (exe, «КАК ИГРАТЬ.txt», лицензии) → размер и контрольная сумма в консоль. Обнови «КАК ИГРАТЬ.txt» под exe.
- Проверь, что экспортированная игра запускается, проходит дымовой прогон с ботом (CLI-флаги в экспортированной сборке тоже должны работать) и играет по сети с версией из редактора.
- Релиз на GitHub **не публикуй сам**. Подготовь архив и текст релиза, а публикацию оставь пользователю (или сделай только по его явной команде).

## 2. Мобы на C++ (GDExtension)

**Подготовка**
- `godot-cpp` той ветки или тега, которые соответствуют Godot 4.7. Сборка через SCons, компилятор MSVC Build Tools (или MinGW, если MSVC нет).
- Что нужно поставить — поставь. Инструкцию для второй машины запиши в `docs/BUILD.md`.
- Код расширения — в `native/`. Собранная `.dll` лежит в `bin/` и **коммитится**, чтобы на машине без компилятора игра работала.

**Что переносить**
- Серверная симуляция из `mob_manager.gd`:
  - сетка соседей и запросы по радиусу;
  - расталкивание;
  - движение с препятствиями и стенами;
  - выбор цели, поводок и гистерезис;
  - кодирование снимка.
- Решения о способностях мобов и боссов можно оставить в GDScript, если они редкие: 2–3 раза в секунду. C++ отдаёт быстрые запросы (соседи, ближайший герой, кто в зоне). Решение о границе — в DECISIONS.
- Визуал, анимации и MultiMesh клиента остаются в GDScript, если замер не покажет, что они тоже узкое место. Это отдельный пункт, только по результатам замера.

**Требования**
- **Запасной путь обязателен.** Если `.dll` не загрузилась, игра работает на GDScript-версии. Флаг `--mobsim=gd|cpp` для сравнения.
- **Эквивалентность.** Тест: одно зерно, одна волна, N тиков на обоих путях. Позиции и состояния совпадают с допуском. Скрипт теста — в `tools/`.
- **Замер:** время серверного тика мобов при 200 / 500 / 1000 мобах до и после, FPS на хосте. Таблица в отчёт. Флаг `--stress=<N>` — заспавнить N мобов.
